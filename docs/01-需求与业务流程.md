# 需求与业务流程

## 1. 项目目标

传统汽车维修记录通常由维修商单独保存，车主、二手车买家和其他维修商难以确认记录是否完整、真实和被修改过。本系统通过“链下保存详情、链上保存摘要”的方式，提供可验证的维修凭证。

区块链解决的是记录上链后的防篡改和可追溯问题。维修商在首次录入时提供的信息仍需要通过业务审核、凭证或管理员机制保证来源可靠。

## 2. 功能范围

### 2.1 用户登录与身份

- 用户使用账号密码登录系统；
- 后端使用 JWT 维护登录状态；
- 用户具有车主、维修商或管理员角色；
- 后端通过 Geth 解锁账户或私钥完成统一链上写入，链上合约记录实际交易账户；
- 第一版不把私钥保存在前端或数据库中。

### 2.2 车辆信息

- 车主新增和查看本人车辆；
- 维修商可以选择待维修车辆；
- VIN 或车辆编号必须唯一；
- 按车辆查看维修历史。

### 2.3 维修记录

维修商录入以下信息：

- 车辆编号和 VIN；
- 维修项目和故障描述；
- 维修时间；
- 维修时里程；
- 使用配件；
- 维修费用；
- 质保期限；
- 维修备注。

提交记录后，系统执行以下操作：

```text
校验表单
  -> 保存链下业务详情
  -> 按固定字段生成标准 JSON
  -> 计算 repairHash
  -> 调用智能合约写入摘要
  -> 保存 transactionHash
  -> 生成维修凭证
```

### 2.4 维修凭证

每次维修生成一个唯一凭证，包含：

- 凭证编号；
- 车辆信息；
- 维修商信息；
- 维修项目；
- 维修时间；
- 质保开始和结束时间；
- 数据 Hash；
- 区块链交易 Hash；
- 凭证状态；
- 验证二维码。

### 2.5 凭证验证

用户输入凭证编号后，系统：

1. 查询链下维修详情；
2. 按相同规则重新计算 Hash；
3. 查询智能合约中的链上 Hash；
4. 比较两个 Hash；
5. 检查凭证是否存在或已撤销；
6. 返回验证结果和质保状态。

验证结果包括：

- 验证通过：链上记录存在且 Hash 一致；
- 验证失败：记录不存在、Hash 不一致或凭证已撤销；
- 质保中：当前时间未超过质保结束时间；
- 已过期：当前时间超过质保结束时间。

### 2.6 维修历史追溯

车主登录后自动加载本人名下车辆的全部维修记录；维修商自动加载自己录入的全部维修记录；管理员可以查看平台全部记录。系统按照维修时间倒序展示，并支持按车辆编号、VIN、凭证号和维修项目筛选，同时可以查看每一条凭证的验证结果。

### 2.7 异常识别

第一版采用规则方法：

- 当前里程小于该车辆上一次维修里程：里程倒退；
- 同一车辆、同一时间和同一项目重复：重复记录；
- 维修时间晚于当前时间：时间异常；
- 链下 Hash 与链上 Hash 不一致：疑似篡改；
- 同一车辆在短时间内重复维修：频繁维修预警。

### 2.8 数据统计

管理员可以查看：

- 维修记录总数；
- 车辆总数；
- 各类维修项目数量；
- 质保中和已过期记录数量；
- 异常记录数量；
- 各月份维修次数；
- 质保中、已过期、未开始和已撤销记录数量；
- 维修类型按数量取 Top 15，其余项目合并为“其他”。

## 3. 核心业务流程

### 3.1 正常存证流程

```text
维修商登录
  -> 选择车辆
  -> 填写维修记录
  -> 系统生成 Hash
  -> 调用智能合约
  -> 取得交易 Hash
  -> 生成维修凭证
  -> 车主查看凭证
```

### 3.2 篡改检测流程

```text
用户查询凭证
  -> 读取链下维修详情
  -> 重新计算 Hash
  -> 读取链上 Hash
  -> 两者一致：验证通过
  -> 两者不一致：提示记录可能被篡改
```

### 3.3 凭证撤销流程

区块链数据不能直接删除。若维修商发现录入错误，管理员可以将凭证设置为撤销状态，并重新创建正确凭证。对于已经上链的凭证，系统调用合约的 `revokeRepairProof` 写入链上撤销状态，交易确认成功后同步更新 MySQL，并保留原凭证、撤销原因和撤销交易 Hash，保证历史过程可追溯。

## 4. 非功能需求

- 可靠性：重要业务操作需要返回明确的成功或失败原因；
- 安全性：密码加密存储，接口进行角色权限校验；
- 可追溯性：维修详情、Hash 和交易 Hash 相互关联；
- 易用性：验证页面能够直接展示结论，不要求用户理解区块链技术；
- 可演示性：本地环境可以完成完整存证和验证流程。

## 5. 答辩演示流程

1. 维修商新增一条维修记录；
2. 展示生成的凭证编号和交易 Hash；
3. 车主查询车辆维修历史；
4. 验证原始凭证并显示“验证通过”；
5. 修改数据库中的维修项目或里程；
6. 再次验证并显示“Hash 不一致，记录可能被篡改”；
7. 恢复或重新生成记录，展示质保中和已过期两种状态。
